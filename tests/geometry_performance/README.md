# ABC478 Gを使った幾何ライブラリの速度改善（2026-10-07）

対象: [ABC478 G - Division Point Hull](https://atcoder.jp/contests/abc478/tasks/abc478_g)。
問題の制約はN≤100,000、1≤p<q≤10、|座標|≤10^7、制限時間4秒。
提出された幾何・有理数・凸包コードを `baseline.rs` に保存した。
比較時のI/Oのみ、全版に同じ標準ライブラリの簡易パーサを使う。
外部ジャッジへの送信は行っていない。

## 原因と変更

分割統治と、左の点群にq/(p+q)、右の点群にp/(p+q)を掛けたMinkowski和を
マージする方針は正しい。旧 `Ratio128::new(p+q,q)` も引数順は正しい。

ただし入力整数を最初からRatioに変換すると、凸包の向き判定や辺の角度比較で、
繰り返し有理数の差・積・約分を行う。入力が `Ratio` でも幾何演算の計算型は
互換性と範囲確保のため `Ratio128` に拡張される。
さらに各再帰の左右区間を `ConvexHull::new` で毎回ソートしている。

ライブラリの変更:

- `GeometryCoordinate::cmp_turn` を追加。既存型・独自実装はdefaultで従来の判定に対応。
- Ratio/Ratio128の向き判定は、共通分母でi128座標に変換できる場合、差・積の有理数約分を省略。
- 有理数の2積比較も、整数分子・分母の積が収まる場合は約分を省略。
- i128の2積比較は、checked積が両方収まるときに直接比較。巨大値では既存の連分数比較にfallback。
- Ratio→Ratio128の拡張は、既約であることを利用して既存の `From` 変換を使い、再約分を省略。
- Ratioの整数同士の加減乗算は、checked整数演算を直接使用。無限大処理とoverflow検出は維持。

どの高速経路も成功した場合のみ使用する。失敗時は従来の厳密な演算へ戻し、
f64・epsilon・wrapは使わない。既存の座標型・返り値の型は変更していない。
このため、既存のRatio64入力をそのまま使える。

## この問題での推奨用法

[examples/abc478_g.rs](../../examples/abc478_g.rs) は、共通分母を払って
`q*P_i+p*P_j` の凸包を整数座標で作る。
最後に面積の2倍を `2*(p+q)^2` で割り、有理数へ変換して約分する。
この問題の内分点の座標分母は必ずp+qの約数なので、途中で有理数を使う必要がない。

入力の凸包と内分点の整数分子の凸包を再帰から両方返し、入力の凸包をマージで再利用する。
元の点群の凸包構築に関しては、各深さで再ソートするO(N log²N)の処理を
凸包マージのO(N log N)の処理へ置き換えられる。
合成した結果凸包の処理量は各再帰での頂点数にも依存する。

制約内では整数分子の各座標の絶対値は(p+q)*10^7≤1.9*10^8。
差・内積・外積・面積をi128で処理するため、今回は十分に範囲に収まる。
最終面積の2倍は座標の外接正方形から2*(3.8*10^8)^2以下。

`abc478_g_submission.rs` はincludeを展開した単独提出用の生成済みファイル。
ソースの変更後は再展開が必要。サンプルをローカルで確認済み。

## 実測

10万点、`rustc --edition=2021 -O`、各2回。
環境・各計測値・答えは `results.json` に保存。
下表は秒の範囲。AtCoderの実行時間・ACを保証する結果ではない。

|入力|提出の演算を再現|ライブラリだけ更新|整数化＋子の凸包再利用（更新後）|
|---|---:|---:|---:|
|ランダム|2.19–2.20|1.16–1.17|0.17–0.18|
|円周・周回順|2.55–2.59|1.37–1.39|0.19–0.20|
|円周・シャッフル|5.61–6.36|3.21–3.35|0.41–0.42|
|一直線|0.78–0.91|0.37–0.39|0.08–0.11|
|全点一致|0.11–0.12|0.10–0.11|0.08–0.09|

旧ライブラリで整数化した版、更新後でも区間の凸包を再構築する版も同時に測定した。
例えばランダム入力では、更新後整数版の再構築が約0.223秒、子の凸包再利用が約0.174秒。
シャッフル円周ではソート再利用の差は今回の測定誤差と同程度だった。
主な改善は有理数を避けることと整数の判定の高速化。

円周データ生成にだけsin/cosの丸めを使う。解法・比較・面積計算は全て厳密。
ランダムstressだけでなく、多数の境界頂点・一直線・重複の形状も確認した。

## 再現と検証

```sh
python3 tests/geometry_performance/check.py --repeat 2
cargo test --offline --test geometry --test convexhull --test ratio
cargo test --offline --release --test geometry --test convexhull --test ratio
python3 tests/check_ratio.py --output /tmp/geometry_ratio_check.json
```

比較する全5版で公式サンプル3件、小ケース200件の全頂点対生成・独立凸包・
面積oracleと一致。10万点の5形状でも出力一致。
基礎幾何11本・凸包10本・有理数11本の計32テストをdebug/releaseで確認。
追加の4,000三角形では高速化した有理数の向き判定を従来の厳密外積と比較し、
LCMや分子の積がi128に収まらないfallbackも確認した。
