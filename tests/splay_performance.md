# Splay木の改善と検証（2026-10-04）

以下は最初の高速化時の記録。NilMonoid/ProdMonoidと追加APIについては [splay_modes.md](splay_modes.md) を参照。

本体: `../src/SegmentTree/splay.rs`。公開trait、Nodeのコンストラクタ、SplayTreeの既存メソッドと引数順は維持。
追加APIは `len()`、`is_empty()`、`from_vec(Vec<S>)`。from_vecはO(n)で平衡形を作る。
各操作の計算量は従来と同じ償却O(log n)。

## 変更

- has_lazyフラグで、未更新ノードのidentity作用・合成・identity再生成を省略。FにPartialEqなどの追加要求はない。
- kthが根から探索位置へ伝播したあと、splayで同じ伝播を繰り返さない。
- 回転中の探索ノードの集約は最後の1回にまとめる。下へ移動した祖先の集約は毎回更新する。
- 区間更新・反転は取り出した区間を根まで回転せず、高々2つの境界祖先を更新する。
- 空の子とのopと、ノード生成時の余分なcloneを省く。未使用の_wフィールドを削除。
- eraseの所有ノード管理をswap_removeで簡略化。
- Box<UnsafeCell<Node>>で所有し、操作はraw pointerで行う。所有用Boxから可変参照を作らず、ノードのアドレスを固定する。

## 正しさに関する修正と前提

- 空区間へのapply/reverseは何もしない。prodは単位元。番兵の集約値・遅延情報を変更しない。
- 添字・区間は境界assertで検出する。l>rもpanic。
- 同梱の例M/MMは、区間和に加算するのに要素数を持たない誤りがあったため、Sをi64から(和,要素数)に修正した。この例を使う場合はinsertへ(value,1)を渡す。独自モノイドのAPIは変えていない。
- mapは単位元を保持し、区間積へ分配可能な作用とする。composition(f,g)はgの後にf。反転と作用は可換であること。
- 非可換モノイドのreverse_prodには、要素順を逆転した区間積へ変換する処理を用意する。

## 計測

ローカルmacOS/arm64、rustc -O。要素数32,768、各操作列100,000回、5回の中央値。
構築は操作時間から除外し、全バックエンドで同じ末尾insertを使う。
区間和とアフィン作用（mod 1,000,000,007）を使用。旧版・新版の取得結果から作るchecksumが一致することも確認。
バックエンドの実行順を交互にし、独立したプロセスで計測する。

| 操作列 | 旧版 | 改善版 | 速度比 |
| --- | ---: | ---: | ---: |
| ランダム区間取得 | 99.62 ms | 53.94 ms | 1.85倍 |
| 近い位置の反復取得 | 9.71 ms | 2.64 ms | 3.67倍 |
| 全体加算＋時々1点取得 | 7.72 ms | 4.30 ms | 1.80倍 |
| アフィン更新・反転・取得 | 109.08 ms | 72.44 ms | 1.51倍 |
| 削除・挿入＋時々区間取得 | 103.52 ms | 52.27 ms | 1.98倍 |

末尾insertによる構築時間は旧版約0.96 ms、改善版約0.93 ms、from_vec約0.96 ms。
末尾insert自体は元からO(n)であり、from_vecの利点は構築直後に平衡形になること。この計測で構築の高速化は主張しない。
数値はこのローカル操作列の結果で、任意のモノイド・操作分布で同じ速度比を保証しない。
個々のサンプルとsource SHA256は `splay_benchmark_results.json` に保存。

```sh
python3 tests/benchmark_splay.py --output tests/splay_benchmark_results.json
```

## 正しさの検証

```sh
cargo test --offline --test splay
cargo test --offline --release --test splay
```

4テストを両プロファイルで通過。初期長0,1,2,3,7,16,31,64の各3seedで計60,000操作を配列と比較。
区間積が非可換な列連結と、合成順で結果が変わるアフィン作用を使用。
空区間、全区間、挿入・削除前の未伝播反転と作用、全削除後の再利用、境界違反、10万要素の極端に深い木と一括構築を検証。
親子ポインタ、要素数、区間積、所有ノードのidx、番兵の不変条件も検査。
既存の本体テストを含め22本がdebug/releaseで通過。
Miriはこの環境にないため未実行。Library Checkerへの提出も今回未実施。

旧版は比較用に `support/splay_baseline.rs` へ保存しており、実用には本体srcを使う。
