# IntervalSetV 検証・性能比較

2026-10-06、macOS arm64、rustc 1.93.0、rustc -O。
比較元は今回の変更直前の Vec で変更記録を返す実装。
[比較元](support/intervalsetv_before_extract.rs)を固定している。

## 正しさ

`cargo test --test intervalsetv` / `cargo test --release --test intervalsetv`：3テスト成功。

- 6点が未登録/値0/値1の729状態、端点 -1..=7、削除/値0挿入/値1挿入の177,147操作。
- 旧版との変更記録内容・順序・最終区間を比較。
- 変更記録を再適用して集合を復元し、各点の値を単純モデルと比較。
- 全ての記録消費途中位置で破棄し、最後まで消費した場合と比較。
- 通常の insert/remove と記録ありの操作の一致。
- 10万操作の連続更新、i64::MIN / MAX、同値区間の連鎖統合。

旧実装は、左端ちょうどにある異値区間を上書きした場合などに、
その左側との間に同値の隣接区間が残ることがある。
今回は変更記録・区間表現の互換性を維持し、この挙動も旧版に合わせている。
そのため、右端の拡張は一つで止まると仮定せず、一つの range で同値の連鎖を読み、
最終的な抽出範囲を決める。

## 性能

`python3 tests/run_intervalsetv_benchmark.py` で再測定可能。
同一バイナリに両実装を含め、各条件5回、順序を交互に変えた中央値。
各実行で結果のチェックサムも比較。

初期区間数65,536、値は位置によって0/1/2。
noop/shorten/randomは100万操作。
noopは既存区間内への同じ値の挿入（旧版同様、変更記録自体は返す）。
shortenは右側2点の削除・挿入。
randomは長さ1..64、値0..3の挿入・削除。
bulk_kは初期集合を複製し、k区間ずつ値3に統合して削除する処理を16回。

## 実装

Rust 1.91 以降の BTreeMap::extract_if が必要。
境界で発生する記録を固定長バッファに置き、途中区間は extract_if で順に削除して返す。
イテレータを作成する時点で境界処理と追加区間の挿入を行い、消費時に抽出を進める。
抽出中は集合を借用し、Drop で残りを抽出する。
左端が変わらない短縮は、削除・再挿入をせず右端を書き換える。
通常の insert/remove も同じ処理を利用する。
