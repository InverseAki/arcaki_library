# PointAddRectangleSum 高速化（2026-10-22）

Gemini4-Argon のユーザー添付案を出発点に18設定を比較し、実測で有効な組合せを本体へ反映した。既存の公開メソッド・型制約・半開矩形・回答順・solve 後の消去を維持。公開の汎用 BIT は変更していない。

## 採用した変更

- x 順のソートを一度だけ行い、時間ブロックで安定分割。二つの作業配列を交互に使い、書き戻しを省略する。
- 連続する Add 群と直後の Query 群をまとめ、再帰の深さを削減する。
- 座標の所有権をイベントへ移し、ソート後に x を破棄。再帰用イベントは16バイト。
- 重み0、空矩形、圧縮後に空になる y 区間、最後の非空矩形より後の更新を除外。質問イベントが一つもできなかった場合はソート前に終了。
- 内部専用 i64 BIT では共通祖先での区間和打ち切り、境界チェック省略、wrapping 演算を使用する。公開 BIT の浮動小数点を含む評価順序や範囲外アクセス時のチェックは維持。
- BIT をゼロに戻す方法を、追加数 > y 座標数 / 64 なら全消去、それ以外なら逆加算に切り替える。
- 32イベント以下の部分問題を直接計算し、下層の分割・コピー・BIT操作を省略する。これは添付案にない追加最適化。
- 静的・動的でイベント構築を共通化し、静的の場合は x のみを比較する。

## 実測から採用しなかった案

- 添付案の上端探索を ys[lo..] に限定する処理は、本環境では全域探索より遅かった。30万操作 query_heavy は0.1454秒→全域探索0.1408秒、静的15万点+15万質問は0.0419秒→0.0360秒。
- 初期点の座標変換を x 走査中に遅延すると静的ケースが遅くなった。先に順位へ変換すると同ケース0.0358秒。最終版は事前変換と全域探索を組み合わせた。
- 追加点の順位探索を binary_search に変える案は安定した改善がなく不採用。
- リセット時に逆加算する代わりに各経路を直接0で上書きする案は blocks などで遅く、不採用。
- cutoff 16は重複座標、64は更新偏重や整列入力で勝つ場面があるが、通常混在と質問偏重を含む折衷として32を採用。
- クリア係数4/16/64/256を比較。64と256の差は小さく、全消去を増やしすぎない64を採用。これはCPUに依存する調整値。
- 通常の2回のprefix和は一部ケースで僅かに速いが一貫せず、共通祖先打ち切りを維持。
- 回答の符号反転のif版は一貫した優位がなかった。ビット演算版を維持するが、機械語が必ず無分岐になるとは主張しない。
- 全境界チェックを外す案は採用していない。unsafeは内部BITの有効範囲に限定し、回答配列・安定分割の書込み・ブロック累積数には安全な添字アクセスを使う。

## 正しさ・互換性・安全性

- 既存の24,000操作列の愚直比較、初期点のbuild/prepend比較、i32/i64/u64/i128、String、Cloneしないx型、空矩形、重複、負数、solve後の再利用を検証。
- 追加10,000操作列ではブロック長1〜65、重み0・i64::MIN/MAX・ランダム64bit重みをwrapping愚直解と比較。
- 内部BITは長さ1〜130の全区間を検証し、逆加算後の全セル0も確認。初期点と動的更新でのi64::MIN相殺も確認。
- Rust 1.93.0と1.89.0のdebug/releaseで確認。公開BITでは浮動小数点・l>rを含む既存のprefix差の評価順と、範囲外gのpanicを確認。
- 内部の重み計算はmod 2^64のwrappingで統一。最終数学的回答がi64内なら中間和があふれても正しい結果になる。回答自体が範囲外ならwrapする。これは従来debug版の中間オーバーフローpanicとは異なる。
- 16バイト表現に伴い、質問数と圧縮後のy座標数は各 i32::MAX 以下。範囲外は明示的assertで拒否し、無検査の切り捨てはしない。APIのシグネチャは同じだが、この巨大入力の上限は新設。
- BIT更新順位は圧縮済み点の順位、質問端点はpartition_pointで得た0..=yn。BITはyn+1要素を確保する。再帰開始時・終了時は全セル0で、親の寄与を計算してから消去し子へ進むため、全消去が他の寄与を破壊しない。
- xが等しい場合は全質問を更新より先に並べる。直接計算でもそれ以前のイベントだけを参照し、時刻ブロック条件を検査するので半開区間を保つ。

## 計算量

初期点N、操作M、有効ブロック数B、異なる更新y座標数Yとすると、O((N+M) log(N+M+1) + M log(B+1) log(Y+1)) 時間、O(N+M) 空間。各再帰のソートはなくなるが、BITの対数因子は残るため、一般の場合にO(M log M)へ改善するわけではない。
