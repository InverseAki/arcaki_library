# Gemini4-Argon の指摘を受けた VebTree 高速化

2026-10-25。前回版を `support/veb_argon/baseline.rs` に固定して比較し、30以上の候補・組合せを実験した。公開API・範囲外処理・空集合の戻り値・文字列の意味は変更していない。`Predecessor64` 本体は変更していない。

## 採用した構造

- 下位ビット列・middle・vEBの圧縮葉のビット列を単一 `Vec<u64>` に統合。再帰部分のメタデータは `Vec<VebNode>` と `Box` のまま。
- 64個以下は1ワード、4096個以下は2段、262144個以下は3段のビット演算。2段/3段の処理はconstジェネリクスで分けた。これを超える部分は6ビット単位で分割する再帰vEB。
- 圧縮葉でも最小値をビット列から除外。要素1個の挿入・削除で余分な葉の更新を避ける。空の内部ノードは `min=usize::MAX, max=0`。公開 `max()` の空集合結果は従来通り `usize::MAX`。
- `chunks_exact(64)` と圧縮葉の一括構築を使用。3段以上の要約は挿入で構築する。
- 文字列変換は各バイトがASCIIの `'1'` と完全一致するかをSWARで判定して詰める。任意の有効UTF-8文字列で元の動作を維持。

上位vEBが管理するのは4096位置ごとの非空状態である。実値域 U<=2^30 では上位も固定段数のビット演算になり、ヒープ上の再帰ノードをたどる必要がない。それ以上の領域も再帰で対応し、値域を狭める特化は行っていない。
更新・隣接検索 O(1+log log max(U,2))、所属判定・最小・最大・空判定 O(1)、空間 O(ceil(U/64)) ワード。領域全体を確保する点は従来と同じ。

## 指摘ごとの結果

|指摘|実験・採否|
|---|---|
|① strictをinclusiveへずらす|`shifted`等。64ビット境界で有利だが通常の検索やE2Eで安定した改善がなく不採用。usize::MAX/0の仕様は全候補で保持。|
|② マスクの単一シフト|`masks`等。コンパイラによる同等の最適化もあり安定した改善なし。新しい圧縮葉内部には単一シフトを使用。|
|③ leading_zerosのXOR化|`xor`。実機では改善せず不採用。|
|④ removeのold==mask|`remove_one`, `flat_remove`。測定で安定した改善なし。元の判定を維持。|
|⑤ 空max=0|`sentinel`単独はほぼ同等。圧縮葉の更新・検索との組合せに採用。最小最大の更新・空集合復帰も検証。|
|⑥ unchecked拡大|`unchecked`, `unchecked_nodes`, `flat_unchecked`。ノード全体のunchecked化は安定した上積みがなく不採用。検証済みの葉/middleアクセスにだけ既存のunsafeヘルパーを使用。|
|⑦ 6ビット単位の分割|単独ではほぼ同等。葉圧縮と合わせて採用。|
|⑧ 葉をu64へ圧縮|`packed`から発展させ採用。葉ごとの64バイトのVebNodeを使わず、8バイトのビット列を共有アリーナに置く。構造全体のメモリが1/8になるわけではない。|
|⑨ 単一アリーナ|`arena`, `packed_arena`, `flat`。操作と大きい値域で改善。入力Vecの拡張費用は増えるため構築も別測定。|
|⑩ 子の最小最大による短絡|`shortcut`。元のinline(always)ラッパーでも短絡され、追加の分岐に安定した効果なし。|
|⑪ 全体min/maxキャッシュ|`global_cache`。空集合・端の検索には有効だが更新が遅くなるため不採用。|
|⑫ ブロックcache・遅延vEB・固定段数化|`block_cache`と実値を直接管理する`pure`は更新/所属判定で損失が大きく不採用。上位の圧縮葉への最小値分離と2段/3段の固定処理は採用。|
|⑬ ボトムアップ構築|一時presence配列を作る`bottomup`は遅い。追加配列を作らない`flat_build`を採用。|
|⑭ 文字列SWAR|最下位ビットだけを読む案は`'3'`等まで1にして契約違反。完全一致を計算する方式に修正し採用。|

主な発展は `packed → packed_arena → flat_build → minimum → packed3 → specialized`。個別の小変更と同時に、組合せでも計測した。ノードサイズの削減をそのまま時間短縮やRSS削減とみなしていない。

## 最終コードの操作計測

Rust 1.89.0、aarch64-apple-darwin、`rustc -O`、CPU指定なし。固定seed・実装順ローテーション・毎操作で集合をblack_boxへ渡す。各条件100万操作×9回の中央値を取り、別プロセスで同じ測定を2回行った。前回のベンチマークからはblack_boxの位置と境界ケースを追加しているため、古いCSVとの絶対ns比較には使わない。

通常領域は64/4096/262144/16777216、strideは2/64/4096/Uの重複なし。大領域は2^24/2^28、strideは4096/65536/1048576/U。stride区間ごとに1個をランダム配置する。更新は初期位置で有無を切替、一部は重複・不在操作。mixedは約半数が更新。empty/contains/extrema/64ビット境界検索も含む。初期構築と破棄は計測外。すべての実装でチェックサム一致。

倍率は比較元の時間 / 現行VebTreeの時間。1より大きければ現行が速い。全条件は等重みの幾何平均で、代表的な利用頻度を仮定した値ではない。

## 入出力込み・RSS

値域1000万、100万操作、共通のI/Oコード、11回の中央値。起動・構築・入力・出力ファイルへの書き込み・破棄を含む。別プロセス群で2回実行。全出力一致、小ケースはPython整列リストとも10000操作を照合。RSSはwait4による各子プロセスのピークで、入力・出力バッファを含む。

|分布|前回 ms (2回目)|64分木 ms (2回目)|現行 ms (2回目)|前回比 1回目 / 2回目|64分木比 1回目 / 2回目|現行 RSS MiB (2回目)|
|---|---:|---:|---:|---:|---:|---:|
|random|24.581|24.483|24.130|0.997 / 1.019|0.996 / 1.015|22.56|
|sparse|35.349|33.297|31.371|1.011 / 1.127|1.024 / 1.061|22.56|
|all0|23.209|23.229|22.751|1.006 / 1.020|1.001 / 1.021|22.56|
|all1|25.950|28.865|25.551|1.065 / 1.016|1.002 / 1.130|22.56|
|query012|19.050|18.851|18.721|1.009 / 1.018|0.999 / 1.007|22.56|
|spaced|27.627|27.211|27.267|1.044 / 1.013|0.989 / 0.998|22.56|

randomは初期半分存在の全種類操作、sparseは10要素だけの隣接検索、all0は空集合への検索・所属判定、all1は全要素ありから削除・検索・所属判定、query012は挿入・削除・所属判定のみ。spacedは4096ごとに1個を配置し、更新位置も4096の倍数とする。小さい差やrun間で逆転する条件は安定した高速化とはみなさない。常に64分木を上回るわけではない。

## 検証と再現

- Rust 1.89.0のdebug/releaseで `predecessor64` 14件、`veb_tree` 7件、`veb_tree_invariants` 2件を通過。
- 全状態（サイズ10まで）、BTreeSet照合、範囲外panic後の状態、Clone、UTF-8、全コンストラクタ、空集合への復帰。
- 公開APIは2^28付近の値域も検証。圧縮葉を超える再帰は内部ノード単体を2^24+1まで検証し、巨大な公開値域を確保せず確認。
- arenaの範囲・葉と要約の一致・最小値の非重複・cached min/max・末尾の部分クラスタを検証。
- 外部ジャッジ提出・公式ジェネレータでの検証は未実施。性能はこの実機でのローカル結果。

`arcaki_library` から実行する。結果ファイルは同名なら上書きする。

```sh
cargo +1.89.0 test --offline --test predecessor64 --test veb_tree --test veb_tree_invariants
cargo +1.89.0 test --offline --release --test predecessor64 --test veb_tree --test veb_tree_invariants
python3 tests/run_veb_argon.py --model --variants baseline,pred,current --output veb_argon_verify
python3 tests/run_veb_argon.py --variants baseline,pred,current --count 1000000 --repeats 9 --output veb_argon_accepted
python3 tests/run_veb_argon.py --large --variants baseline,pred,current --count 1000000 --repeats 9 --output veb_argon_accepted_large
python3 tests/run_veb_argon_e2e.py --variants baseline,pred,current --repeats 11 --output veb_argon_accepted_e2e
python3 tests/run_veb_argon.py --only constructors --variants baseline,pred,current --repeats 7 --output veb_argon_accepted_constructors
```

操作/E2Eの2回目は同じコマンドでoutput末尾に `_repeat` を付けた。CSVは個別試行、JSONは環境・引数・ソースSHA256・操作中央値。`support/veb_argon/*.rs` と `run_veb_argon.py` 内の変換関数で候補を再現できる。`veb_argon_accepted*` が採用後のソースの結果で、それ以前の `final` を含む結果名は途中候補の記録。
