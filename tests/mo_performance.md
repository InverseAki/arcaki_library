# Mo 高速化の比較 (2026-10-21)

`new(data) → add_query(l, r, qd) → solve(&mut state)`、公開 trait、公開 `MoQuery`、登録順の回答、拡大を先に行う処理順を維持した。

## 採用

- Hilbert 順序を再帰からビットごとのループへ変更。反転も含めて旧実装と同じキーを生成する。
- 4方向の移動を、区間スライスの前向き・逆向きイテレータへ変更。各区間の境界を確認後、要素ごとの添字アクセスを避ける。追加の `unsafe` は不要。

## 比較と見送り

`baseline` は変更前ソース、`iterative` は非再帰化のみ、`slices` は非再帰化とスライス走査、`unchecked` は非再帰化と `get_unchecked` (登録時の区間検査つき)、`flat` は非再帰化・スライス走査・キーを持つクエリ配列の直接ソート、`uninit` は非再帰化・スライス走査・パニック時の破棄ガード付き `MaybeUninit`、`adopted` は採用した実際のソース。

- 直接ソート: 小さいクエリでは有利な場合もあったが、大きいクエリデータでは悪化。特に query_heavy の大きいデータでは旧版の約1.49倍の時間になったため見送り。クエリそのものをソートで動かすコストが増える。
- `get_unchecked`: 安全なスライス走査に対する安定した優位がなかったため見送り。
- `MaybeUninit`: スライス版からの追加効果は条件でばらつき、遅くなる条件もあった。パニック時の回答破棄と未初期化メモリ管理を増やすほどの安定した改善がなく見送り。回答型により結果は変わり得る。
- Gemini の最初の非再帰コードは下位桁の反転を省いていたため使っていない。掲載された結果配列コードの `Vec` の `transmute` も使っていない。

## 測定

ARM64 macOS / rustc 1.93.0、`rustc --edition=2021 -O`。7分布 × 2種類の付加データ × 7実装 × 7回 = 686測定。実装を回す順序をずらし、中央値で比較した。乱数種は固定。

種類数を管理する状態を使い、構築・クエリ登録・順序生成・ソート・区間移動・回答生成・回答のチェックサムまでを含む。最後のソルバと回答の破棄は計測外。全実装の回答チェックサムを照合した。

通常は `Query = [u64; 0]`, `Ans = [u64; 1]`、大きいデータでは `Query = [u64; 32]`, `Ans = [u64; 16]`。後者はクエリと回答の両方を大きくしている。クエリ型・回答型・状態の処理コストが違えば改善率も変わる。

| 分布 | N | Q | 旧版 ms | 採用版 ms | 速度比 | 大きいデータの速度比 |
|---|---:|---:|---:|---:|---:|---:|
| random | 200000 | 200000 | 68.781 | 55.281 | 1.244x | 1.227x |
| short | 200000 | 200000 | 22.650 | 18.998 | 1.192x | 1.057x |
| clustered | 200000 | 200000 | 19.649 | 16.537 | 1.188x | 1.001x |
| duplicates | 200000 | 200000 | 11.394 | 8.827 | 1.291x | 1.118x |
| few | 200000 | 2000 | 5.156 | 4.116 | 1.253x | 1.247x |
| tiny | 128 | 256 | 0.014 | 0.011 | 1.231x | 1.204x |
| query_heavy | 2000 | 200000 | 14.090 | 12.473 | 1.130x | 1.030x |

`random` は一様な端点、`short` は長さ64未満、`clustered` は8か所付近、`duplicates` は16種類の反復、`few` はクエリ少数、`tiny` は小規模、`query_heavy` は配列に対してクエリ多数。分布生成の詳細は測定コードを参照。

生データは [mo_benchmark_results.json](mo_benchmark_results.json)、旧版は [support/mo_baseline.rs](support/mo_baseline.rs)。再実行はリポジトリで `python3 tests/run_mo_benchmark.py`。候補ソースと実行ファイルは一時ディレクトリに生成される。実行すると結果 JSON を更新する。

## 正しさと互換性

`tests/mo.rs` の6テストが debug/release で成功。

- pow 0..7 の全座標・全回転と、pow 1..32 の各10,000座標を旧再帰版と照合。
- 左右の追加・削除を区別する状態で、小区間全探索、ランダム、飛び離れた区間、空区間、重複を検証。
- 非 Copy のデータ、非 Copy の回答とクエリ、クエリ固有データと ID、ZST、空クエリ、fresh state での再実行、solve 後のクエリ追加を検証。
- 正常終了と add/ans のパニック時に、生成済みの回答がすべて破棄されることを確認。
- 添字が配列外の区間で安全にパニックすることを確認。引き続き呼出側が `l <= r <= data.len()` を満たす必要がある。

既存 `tests/rollback_mo.rs` の7テストも debug/release で成功し、既存 `algorithm_set/examples/mo_distinct.rs` はコンパイル・実行成功。外部ジャッジでの検証や他の CPU での性能保証は含まない。旧版の32ビット座標の Hilbert キー方式も維持している。
