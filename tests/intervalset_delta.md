# IntervalSet Rust 1.89版：被覆差分だけの列挙

[実装](../src/DataStructure/intervalset_rust189.rs)。2026-10-06 に比較し、差分列挙版を採用。
以下の性能測定の対象はRust 1.89対応の重みなし版。現在は1.91以降の [extract_if版](../src/DataStructure/intervalset.rs) も同じ差分・区間ペア形式を返す。値付き版の記録形式は維持する。

## 戻り値の意味

形式は Iterator<Item = (T, T)>。挿入・削除は呼んだメソッドで分かるため、bool は返さない。
insert_with_data は新たに被覆された部分だけを、
remove_with_data は被覆がなくなった部分だけを、左から順に返す。
各区間は空でなく、更新区間の中にある。実際の変化がなければ空イテレータ。

既存が [0,3), [5,8) の場合、insert(2,6) は [(3,5)] のみを返す。
既存が [0,8) の場合、remove(2,6) は [(2,6)] のみを返す。
以前の内部区間の変更記録では、後者は
[(0,8,false), (0,2,true), (6,8,true)] を返していた。

総被覆長は、挿入時は返った区間長を加算し、削除時は減算する。以前と同じ結果になる。
内部BTreeMapのキー単位の記録を再現する戻り値ではない。
Vec・記録用ヒープ領域を確保せず、途中破棄でも更新を完了する。
挿入・削除それぞれ専用のイテレータで処理し、変更のない被覆や分割の残りは返さない。
集合の更新後の区間表現・contains/section の挙動は維持する。

## 検証

実際のrustc 1.89.0で以下を実行し、debug/release各3テスト成功。

```sh
cargo +1.89.0 test --test intervalset_rust189
cargo +1.89.0 test --release --test intervalset_rust189
```

- 256被覆状態と全更新区間の61,952操作を全列挙し、単純モデルから作った差分区間列と完全一致。
- 通常APIと、記録の各位置で途中破棄した結果の一致。
- 10万操作の連続更新・i64::MIN/MAXで、以前の内部記録から計算した総被覆長差と最終集合を比較。

## 性能

以下の測定値は差分版の戻り値からboolを取り除く前のもの。bool削除後は同じ更新経路で、性能の再測定はしていない。

比較元は [変更直前の1.89改善版](support/intervalset_rust189_before_delta.rs)。
macOS arm64、rustc 1.89.0、rustc -O、各条件5回の中央値。
実行順を交互にし、結果チェックサムの一致も確認。

初期区間数65,536、noop/shorten/randomは100万操作。
noopは被覆済み区間内への挿入、shortenは右側2点の削除・挿入、
randomは長さ1..64のランダム更新。
