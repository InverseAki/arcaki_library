# 40ms提出と19msのC++提出の比較

2026-10-21。対象はユーザーが提示したu32版のRust提出と
[C++提出 #402567](https://judge.yosupo.jp/submission/402567)。
C++のページでAC・19msを確認し、表示されたソースを読んだ。

## ソースから確認できた差

両方とも16要素ブロック内のprefix/suffixと、ブロック間のSparse Tableを使う。
基本のデータ構造は同じ。C++はu32最小値向けの実行経路を選んでいる。

| 箇所 | Rust提出 | C++提出 |
| --- | --- | --- |
| 入力の取得 | `read_to_end`でVecへ読み込む | Linuxの通常ファイルを`mmap`する専用入力 |
| 数値の解析 | 1バイトずつ空白・数字の判定と10倍加算 | AVX2で区切り位置を抽出し、複数の十進数をまとめて変換 |
| 質問の読み込み | l/rをそれぞれ読む | 4フィールド、すなわち2質問分を一度に変換 |
| 全体の流れ | 1質問ずつ入力・計算・出力 | 8質問ずつ入力、計算、出力 |
| ブロック内の質問 | 最大16要素の走査 | u32の8要素パックとマスクによるAVX2の最小値計算 |
| prefix/suffixと表の構築 | スカラー走査と自動最適化 | 明示的なAVX2のscan・最小値計算 |
| 隣接ブロック | 中央が空の場合を分岐 | 単位元の追加段を持ち、中央の空区間の分岐を省く |
| 出力の数値化 | 2桁の表 | 4桁の表と固定サイズバッチ |

C++は整形式ASCII、区切りの個数、整数の桁数、Linuxの通常ファイルなどを
前提とした専用経路を使う。汎用の入力ライブラリとして同じ前提を採用するかは
別途設計する必要がある。

## Rust側の分離計測

Rust 1.89.0、`--edition=2021 -O`、aarch64 macOS。
n=q=500,000、値は0〜1,000,000,000のu32。
広い区間と長さ1〜16の区間を固定シードで生成した。

2回のウォームアップ後、9回の中央値。次の表は質問を先に配列へ読み込み、
答えの配列を計算してから出力する分離版の値。
元の1質問ずつのループの内訳や、ジャッジの40msの直接の内訳ではない。
読み込んだ配列のキャッシュ状態、配列確保、プロセス起動・破棄などの影響があり、
各列の中央値の和もプロセス全体時間と同一にはならない。

| 段階 | 広い区間 | 長さ1〜16 |
| --- | ---: | ---: |
| stdinを読み込む | 1.668 ms | 1.590 ms |
| n/qと初期配列を解析 | 3.372 ms | 3.355 ms |
| Sparse Table構築 | 0.979 ms | 0.975 ms |
| 質問を解析して配列へ格納 | 5.721 ms | 5.560 ms |
| 質問の答えを配列へ計算 | 2.784 ms | 5.013 ms |
| 十進表記へ変換・出力 | 3.632 ms | 3.472 ms |

この条件では入力に約11msかかり、構築は約1ms。
構築だけの改善では全体の大幅短縮につながりにくい。
短区間ではブロック内の走査にも改善余地がある。

## 実験と採否

提出コードを基に、入力の整数変換を4桁・8桁単位のSWARへ変更し、
質問を8件ずつ処理した。入力バッファの末尾には32バイトの読み取り可能な
ゼロ領域を追加してから、4/8バイトを非整列ロードしている。
この実験は提出で使用するu32/usize経路を対象としている。

同じ入力・同じ実行で比較した最後の測定:

| 条件 | 40ms提出のコード | SWAR入力＋8質問バッチ |
| --- | ---: | ---: |
| 広い区間 | 22.435 ms | 18.398 ms |
| 長さ1〜16 | 25.498 ms | 21.636 ms |

別の比較実行でも、入力変換・バッチ化の組合せは改善した。
一方、この環境では4桁出力表への変更とブロック内処理のnoinline化は
改善しなかったため、提供する実験版には入れていない。

出力全体を元の提出と照合したほか、145ケースを愚直解と照合した。
u32::MAX、0、10進数の桁境界、ブロック境界、8件バッチの端数、
先頭ゼロ、連続空白、CRLF、末尾改行なしを含む。

生の測定値と条件は
[sparsetable_submission_diagnosis_results.json](sparsetable_submission_diagnosis_results.json)。
実験用の単一ファイルは `/private/tmp/sparsetable_diagnosis/swar_batch8.rs`。

C++のAVX2版はこのarm64環境では実行していない。
19msと40msの差を各最適化へ何msずつ配分できるかは未確定。
Rust実験版もジャッジ未提出であり、ここに示す改善率をジャッジへそのまま換算しない。

優先する順序は、入力の複数整数の一括変換、8件程度のバッチ化、
u32のブロック内処理のSIMD化。質問本体の追加高速化は、
入出力と組み合わせた全体時間で評価する。
